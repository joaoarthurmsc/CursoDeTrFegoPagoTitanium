# Titanium Visual Standard V1

## Objetivo

Imagens existem para reduzir abstração, aproximar o aluno da operação real e tornar o raciocínio mais fácil de reconstruir.

## 1. Google Ads e interfaces operacionais

Quando a aula ensina uma ação, leitura ou diagnóstico dentro do Google Ads, a preferência é por **captura autêntica e atual da interface**.

Padrão:

- screenshot real;
- data da captura;
- fonte identificada;
- zoom disponível;
- recorte limpo;
- destaque visual apenas quando ajuda;
- callouts curtos;
- sequência de screenshots quando o fluxo exigir mais de uma ação.

Não usar imagem gerada por IA fingindo ser screenshot do Google Ads.

## 2. Imagens explicativas

Diagramas, mapas, comparações, fluxos e metáforas visuais podem ser produzidos especificamente para o Titanium.

Eles devem:

- ensinar uma relação;
- ser legíveis em notebook;
- funcionar em tela cheia;
- preservar o visual premium escuro do Titanium;
- evitar ornamentação que não ajuda a aprender.

## 3. Densidade visual

Uma imagem deve justificar o espaço que ocupa.

Não inserir imagem apenas para "quebrar texto".

Preferir imagem quando ela:

- mostra uma interface;
- compara estados;
- apresenta causa e efeito;
- explica um funil;
- mostra arquitetura;
- demonstra uma configuração;
- evidencia dados.

## 4. Padrão de legenda

Capturas reais devem exibir:

`Captura real · fonte · data`

Exemplo:

`Captura real · Google Ads · set/2026`

## 5. Fluxo “Faça comigo”

Aulas operacionais podem usar sequência:

1. veja a tela real;
2. identifique a área destacada;
3. execute no seu ambiente;
4. confirme o resultado esperado;
5. continue para a próxima captura.

## 6. Responsabilidade editorial

A imagem real deve estar coerente com a interface vigente no momento de produção da aula. Se a plataforma mudar de forma material, a captura deve ser substituída.
